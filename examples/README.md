# Examples

Reference walkthroughs of past kickoffs. Add anonymized examples here as you complete them. Useful for:

- Showing future-you what a "good" filled-out brief looks like
- Onboarding collaborators
- Calibrating depth and detail across projects

## Suggested structure

For each example, create a subdirectory with the full set of artifacts:

```
examples/
└── <project-slug>/
    ├── PROJECT_BRIEF.md
    ├── RESEARCH.md
    ├── ARCHITECTURE.md
    ├── CLAUDE.md
    ├── DESIGN.md
    ├── BUILD_PLAN.md
    └── NOTES.md       ← what worked, what didn't, what would I do differently
```

The `NOTES.md` is the most valuable part — it's where the learning compounds.

## When to add an example

After each project's first build phase ships, take 30 minutes and add the kickoff docs here (sanitized of anything sensitive). The artifacts are fresh in your head and the lessons are still vivid.

## What not to put here

- Real customer data
- Credentials or secrets
- Internal commercial details that shouldn't be in a public repo (if this repo goes public)
